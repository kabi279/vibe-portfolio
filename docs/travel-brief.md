# AI 旅游助手 — 产品 Brief（含轻量预订闭环）

## 目标用户（分层）
- **第一类（规划型游客）**：周末或短期假期的自由行游客，希望快速获得个性化行程，不愿花大量时间查攻略。
- **第二类（即买型用户）**：行程确定后，希望在同一界面直接预订推荐酒店或查看交通方案，避免在多App间切换。

## 核心痛点
- **信息割裂**：做攻略在一个地方，订酒店/机票又得切到另一个App，操作成本高。
- **决策焦虑**：不知道推荐的酒店是否方便、价格是否合理，缺乏直观对比。
- **行程调整麻烦**：行程定好后，想换景点或调整预算，缺乏灵活替换能力。

## 产品价值
- **一体化体验**：输入需求后，不仅生成逐日景点行程，还自动匹配推荐酒店（含价格/距离）和交通建议（如高铁/飞机时长）。
- **轻量预订闭环**：点击酒店或交通方案的“预订”按钮，进入模拟下单页，选择房型/班次，使用积分抵扣或虚拟支付，完成模拟预订。
- **可编辑可分享**：支持替换景点、重新生成、保存行程列表和分享摘要。

## 数据与推荐范围（轻量但真实感）
**景点数据**（本地JSON，每城≥10个）  
上海、杭州、成都，含名称、图片、标签、游玩时长、人均花费、区域、室内外、时段建议。

**住宿数据（新增）**（每城3-5家模拟酒店）  
字段：名称、图片、区域（如"市中心/景区附近"）、房型（大床/双床）、参考价格（元/晚）、与当日行程第一站的步行/车行距离、评分（4.5+虚构评分）。

**交通数据（新增）**（仅做展示，不接入实时API）  
针对跨城场景（如"上海→杭州"），提供高铁/大巴的模拟时长和参考票价（如"高铁约1.5小时，票价约70元"）。

## 主用户路径（含预订闭环）
1. **填写需求**：选择目的地、天数（1-5天）、预算、同行人（独自/情侣/亲子/朋友）、兴趣偏好（美食/人文/自然/购物）。
2. **生成行程**：点击生成，加载1-2秒后展示逐日景点安排（含推荐理由和每小时花费）。
3. **推荐住宿与交通**：行程下方自动匹配推荐2-3家酒店（按距离/价格排序），并显示跨城交通建议（如适用）。
4. **预订操作**：点击酒店"预订"按钮 → 选择房型/入住人数 → 进入模拟结算页（显示总价，支持积分抵扣，呼应会员商城） → 提交订单 → 展示"预订成功"页（含虚拟订单号）。
5. **灵活调整**：可替换任意一天景点，或调整偏好后重新生成行程与住宿推荐。
6. **保存与分享**：保存行程到本地列表，或复制分享摘要（含景点+酒店信息）。

**简写路径**：
表单填写 → 生成中 → 行程展示（含住宿/交通推荐） → 点击预订（酒店/交通） → 模拟结算 → 预订成功 → 保存/分享

## 关键指标（埋点事件）- 新增预订漏斗
- `generate_plan`：提交生成请求（记录目的地/天数/预算）
- `swap_poi`：替换景点（记录替换前后地点）
- `click_booking`：点击酒店或交通的“预订”按钮（记录类型：hotel/transport）
- `begin_checkout_travel`：进入预订结算页
- `booking_success`：预订成功（记录金额、消耗积分）
- `save_plan`：保存行程

## 本期明确不做（边界—保持可控）
- 真实大模型 API（完全使用本地推荐引擎，通过规则排序模拟AI感）
- 实时酒店/机票库存与价格（价格写死在本地JSON中，仅做演示）
- 地图路线绘制（无GIS地图，用文字描述"距离XX景点步行10分钟"代替）
- 真实支付（所有预订均为模拟提交，不接入微信/支付宝）
- 多语言支持
- 用户登录系统（沿用设备本地ID或手动选择身份）
